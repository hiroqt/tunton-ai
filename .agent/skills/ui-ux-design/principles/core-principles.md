# Core UX Principles

## User intent before UI
Start from the user's goal, context, frequency, and consequence. A component is a means,
not the goal.

## Information before decoration
Decide what users need to notice, understand, compare, and act on before polishing appearance.

## System before isolated component
Buttons, forms, navigation, settings, tables, notifications, loading, and validation should
behave as systems with coherent rules and states.

## Capability before device label
Design for actual input capabilities—keyboard, touch, pointer, assistive technology, or a
combination—rather than assuming "mobile" or "desktop" tells the whole story.

## State completeness
Important UI should accurately represent the states users can encounter, including loading,
empty, error, success, disabled, partial, offline, and focus states where applicable.

## Immediate acknowledgement
When work takes time, acknowledge the user's action immediately and make progress/status
understandable.

## Honest status
Never make users guess whether something saved, succeeded, failed, or is still processing.

## Recovery proportional to consequence
The greater the cost of a mistake, the stronger the protection and recovery path should be.

## Accessible redundancy
Important meaning should survive without color, hover, precise pointing, animation, or sound.

## Motion with purpose
Movement should communicate continuity, cause/effect, feedback, hierarchy, or attention.

## Consistency with deliberate exceptions
Follow established product conventions unless a purposeful exception creates a clear usability
benefit.
