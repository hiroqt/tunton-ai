# Component UX Review Checklist

- [ ] Primary purpose is clear
- [ ] Semantics and affordances match behavior
- [ ] Default, focus, active, loading, success, error, empty, and disabled states are covered where applicable
- [ ] Feedback is timely and placed appropriately
- [ ] Keyboard/touch/assistive input paths work where in scope
- [ ] Important meaning is not color-only or hover-only
- [ ] Long-running operations communicate progress/state
- [ ] Destructive actions have proportional protection and recovery
- [ ] Responsive behavior is intentional
- [ ] Motion has a purpose and reduced motion is respected
- [ ] Existing design tokens/components are reused where appropriate
